# 紫微斗數 · 星盤流年

传统中式深色鎏金风格的紫微斗数排盘 H5 网站。纯静态，无需构建工具、无需联网。

## 快速开始

**方式一：直接双击**
用浏览器打开 `index.html` 即可。

**方式二：本地服务器（推荐）**
```bash
npm run serve
# 或
python -m http.server 8899
```
然后访问 `http://127.0.0.1:8899`。

> 建议用服务器方式：`file://` 协议下部分浏览器会限制脚本行为
> （Service Worker 在 `file://` 下完全不可用，离线功能会失效）。

**部署上线**：见 [DEPLOY.md](DEPLOY.md)（Cloudflare Pages，含三种方式与验证步骤）。

**跑测试**：
```bash
npm test          # 12 组套件
npm run test:sw   # Service Worker 离线验证（需本机有 Edge/Chrome）
```

## 面向普通人的白话层

紫微斗数原生的表达（紫微、化忌、大限、五行局…）对没接触过的人等于天书。本站专门做了一层翻译，让完全不懂的人也能看懂自己：

| 功能 | 位置 | 说明 |
|---|---|---|
| **白话解读** | 起盘后最顶部 | 先回答「你是个什么样的人」，给出优势 / 课题 / 建议 |
| **四化重点** | 白话解读内 | 把「禄权科忌」翻译成「哪里顺、哪里要花心思」，化忌排最前 |
| **流年白话** | 盘面上方 | 「今年的重心在事业与工作方式」这类直白结论 |
| **宫位白话** | 点任意宫位 | 「这宫管什么」+「你的情况」（星曜逐条翻译） |
| **术语即时注解** | 信息条、各处 | 带虚线下划线的词点一下就地弹出解释，不用跳走 |
| **术语词典** | 页尾入口 | 24 条术语全表，支持搜索 |
| **四步看懂这张盘** | 盘面下方 | 新手导读，告诉先看哪、再看哪 |

**内容与结构分离**：所有解读文案集中在 `js/interpret.js`，改文案不用动逻辑。

**关于借对宫**：命宫无主星时，传统上借对宫星曜来论。本站在解读里会明确说明「你命宫本身没有主星，按传统借对宫 XX 的星来论」，而不是假装命宫有星。

**关于化忌**：传统上把化忌看作「功课」而非凶兆，文案保持这个立场——费力之处往往也是成长最快之处。

## 视觉与动效

深色鎏金主题，刻意的传统中式质感而非通用深色 SaaS：

| 层面 | 处理 |
|---|---|
| 底色 | 偏暖的中性暗色（非纯黑），径向氛围光 + 星点 + SVG 颗粒噪点 |
| 鎏金 | 降饱和到古铜色（`#b8944a`），避免亮黄刺眼 |
| 导航 | 浮动玻璃拟态胶囊（sticky，`backdrop-filter` + 内描边模拟边缘折射） |
| 字体 | 标题宋体 500 字重 + 极淡暖光晕染（补偿宋体小字号在深色底上的断笔）；数字全部 `tabular-nums` |
| 阴影 | 统一光源方向，暖褐色调而非纯黑；抽屉按滑入方向投射 |
| 圆角 | 分三档：容器 `--r-md` / 控件 `--r-sm` / 徽标 `--r-xs` |

**动效**（全部只动 `transform` / `opacity`，GPU 合成，不触发重排）：

| 场景 | 处理 |
|---|---|
| **起盘入场** | 十二宫以命宫为起点依次铺开（`--i` 交错 42ms）+ 中心区随后浮现 |
| **解读分段** | 白话解读按阅读顺序依次浮起：结论 → 标签 → 优势/课题/建议 → 四化 |
| **流年切换** | 只更新高亮 class（不重建 DOM），高亮平滑移动 + 新点亮宫位脉冲 + 虚岁数字滚动 |
| **滚动入场** | 盘面/图例/导读进入视口时浮起（`IntersectionObserver`，只播一次） |
| **宫位聚光** | hover 时金色光晕跟随光标（CSS 变量 `--mx/--my`） |
| **加载态** | 按钮光带扫过（替代通用 spinner） |
| **按钮物理** | hover 时内嵌图标沿对角线位移放大，`:active` 缩放模拟按压 |
| **空态** | 十二宫线框呼吸式明暗 |

设计取舍：

- **不使用 `ease-in-out` / `linear`**，全部自定义贝塞尔（`--ease-glide` / `--ease-breath` / `--ease-sweep`）
- **刻意不用 blur 做入场**：12 格同时跑 `filter: blur()` 会在移动端明显掉帧
- **进场动画延迟到元素可见才播**：盘面在白话解读下方，起盘时通常还在屏幕外，立刻播放等于白播一遍
- **切流年不重建 DOM**：全量 `innerHTML` 重建会让高亮「闪一下」而无法过渡，也丢失节点状态
- 已处理 `prefers-reduced-motion`，并为键盘用户提供 skip-link 与可见 focus 环

**两道防"内容不可见"的保险**（动效失败不能把内容藏起来）：

1. `.reveal` 类由 JS 添加而非写在 HTML 里 —— 脚本失败时内容照常显示
2. 若 `IntersectionObserver` 一个回调都没派发，3 秒后撤掉动效直接显示

### 离线与安装

本应用**没有后端**，排盘全部在本地完成，因此断网时功能完全不受影响。Service Worker 会把应用外壳预缓存，首次访问后即可离线打开。

- 桌面 Chrome / Edge：地址栏出现安装图标，点击即可安装
- iOS Safari：分享 → 添加到主屏幕
- 首次访问需联网一次（用于缓存资源），之后不再需要

> `file://` 协议下不会注册 Service Worker（浏览器限制），但仍可正常使用——离线只是增强。

### 合盘说明

合盘给出的是**相处倾向**而非「合不合」的结论。判断依据是双方命宫主星的组合类型（性情相近 / 一动一静 / 两强相遇 / 两柔相处）。页面底部明确写了这一点，不把传统说法包装成宿命判断。

### 隐私

生辰只在本机流转：写在 URL 查询串里、存在浏览器 localStorage 中，**不发往任何服务器**。页面没有后端，也没有任何统计脚本。清除浏览器数据会同时清掉收藏。

## 排盘引擎

使用开源库 [iztro](https://github.com/SylarLong/iztro)（MIT），随项目内置于 `vendor/iztro.min.js`。

**为什么用现成库**：紫微斗数的安星表（紫微星定位、天府星系、四化、大限起运等）是高度依赖精确查表的数据。手写重建极易产生「看起来专业但系统性错误」的结果，因此本项目直接采用经过验证的开源实现，前端只负责渲染与交互。

排盘准确性验证见 `test-edge.js`：任意命盘恒有 14 主星、4 四化、十二宫名称完整。

### 经实测确认「不是问题」的几处

审查报告提出但**实测不成立**，避免误改：

- **「方向键在部分宫位失灵」**：穷举 12 宫 × 4 方向共 48 种情况，4 步预算与 8 步结果**完全一致**（实际最多连续跳过 2 个中心格）。保留 8 步仅为防御性写法。
- **「流时时辰算错，影响每个用户」**：实测两套公式在 0–22 点结果相同，**仅 23 点**有差异。
- **「闰月参数硬编码错误」**：`byLunar` 第 4 参 `isLeapMonth=false` 是正确默认值；真实缺口是 **UI 没有闰月开关**，不是参数传错。
- **收藏 label 的 XSS**：`safe()` 已完整转义，无问题。
- **事件监听器泄漏**：全是事件委托或随 `innerHTML` 销毁，实测 30 次重渲染无累积。
- **`state` 累积大对象**：`chart`/`liunian` 整体替换，`exportCanvas` 关闭时置 null。

### 已知限制

- **Service Worker 运行时**：headless 环境无法验证缓存是否真的生效，`test-pwa.js` 只覆盖静态正确性（清单指向真实文件）。需在真实浏览器确认。

### 农历闰月

闰月与非闰月会排出**不同的命盘**——不是细节差异。以 2023 年闰二月二十为例：

| 选择 | 阳历 | 命宫 | 五行局 |
|---|---|---|---|
| 二月二十 | 2023-03-11 | 酉 | 木三局 |
| **闰**二月二十 | 2023-04-10 | **戌** | **水二局** |

所以界面上：

1. 选农历时，若该年该月确有闰月，会**自动出现**「这个月是闰 X 月」勾选框
2. 若该年有闰月但不是你选的月份，会有提示告诉你去改月份
3. 勾选状态会写进分享链接（`lm=1`）和收藏记录，回看时不会丢
4. 闰月与普通月的天数可能不同（29/30），填错会被拦下

**实现要点**：`iztro` 的 `byLunar` 在「该月并无闰月」时会**静默忽略** `isLeapMonth` 而不报错，所以不能用返回值判断，必须显式查表。闰月是固定的历史事实，`js/lunar-table.js`（由 `tools/gen-leap-table.js` 生成）覆盖 1900–2100，运行时 O(1)；表未覆盖的年份回退到实时探测。

> **Service Worker 的运行时行为**（缓存是否真的生效）无法在 headless 环境验证——headless 的快照时刻早于 SW 生命周期完成。`test-pwa.js` 验证的是静态正确性（清单指向真实文件、结构完整、图标有效），这也是 PWA 最常见的失败原因。完整的离线验证请在浏览器中手动执行：
>
> ```bash
> node serve.js      # 启动 http://127.0.0.1:8899
> ```
> 1. 打开页面，等 2 秒让 SW 安装
> 2. DevTools → Application → Service Workers，确认状态为 activated
> 3. Application → Cache Storage → `ziwei-v1`，确认列出 12 个资源
> 4. 勾选 Network 的 Offline，刷新页面 —— 应仍能正常排盘

## 实现要点

**十二宫网格布局**：4×4 网格，外围 12 格按地支定位（寅在左下，顺时针绕行），中间 2×2 为中心信息区。

```
巳 午 未 申
辰         酉
卯         戌
寅 丑 子 亥
```

**时辰参数**：iztro 的 `timeIndex` 为 0–12，其中 0=早子时、1–11=丑至亥、12=晚子时。

**真太阳时**：校正后必须同时更新「日期」和「时支索引」。只改日期会漏掉时辰变化（例如乌鲁木齐早子时实际落在前一日亥时），导致日柱与时柱不一致。

**盘面渲染复用**：`buildChartHTML(astrolabe, opts)` 是纯函数，主盘与合盘的双盘并排共用同一套渲染逻辑（`interactive: false` 时星名渲染为纯文本而非按钮，避免双重交互语义）。不要把渲染逻辑写两遍——那必然分叉。

**对比盘的行高必须固定**：中心区用 `grid-row: 2 / 4` 跨两行。若容器用 `grid-template-rows: repeat(4, auto)`，跨行元素会与外围格子错位。对比盘统一用固定行高。

**`[hidden]` 陷阱**：`.drawer`／`.empty-state`／`.longitude-row` 都带 `hidden` 属性，但自身声明了 `display: flex`。作者样式的 `display` 会覆盖 `hidden` 的默认 `display: none`，导致元素隐藏失效。样式表顶部的 `[hidden] { display: none !important; }` 是必需的，不是冗余。

**宫位 hover 特异性**：`.cell:hover` 与 `.cell.is-ming` 特异性相同（0,2,0），同分时后者按源码顺序胜出，会让命宫没有 hover 反馈。现在 hover 反馈通过独立的 `::after` 覆盖层实现，不参与背景声明竞争，任何宫位都有反馈。

**移动端盘面**：390px 压四列会毁掉星名可读性，因此窄屏给 `.chart` 固定 `132px × 4` 并让 `.chart-wrap` 横向滚动，保证十二宫完整可读。
